# DR-0002: New-tab scope = links rendered inside the case-study body; `#` anchors, site chrome, and /workflow/ stay same-tab

- Date: 2026-11-23
- Status: accepted (pending Pedro's confirm; flip is a one-line scope change)
- Context: "Make any link from case studies open in new tabs." Scope candidates: (a) every link on a case-study page including the global nav and the prev/next buttonslider; (b) only links in the case-study content (the `mdhero`/`mdpage` output: `::: callout` links, "lead | href | title" link lists, inline markdown links); (c) links from other pages TO the case studies (home work cards in `src/_data/work.json`).
- Decision: (b). For the four case-study pages only, the renderer adds `target="_blank" rel="noopener noreferrer"` to every emitted `<a>` whose href does not start with `#`. The Ticket 1 section-nav anchors and any in-content `#` anchors stay same-tab by construction. Global nav, home cards, buttonslider prev/next unchanged. `/workflow/` shares the `mdpage` filter and stays same-tab (opt-in flag per template, not a global renderer change).
- Rationale: content links are references and live demos (e.g. teachr `try-app` callout -> `../teachr-app/?view=library`); opening them in a new tab preserves the case-study scroll position, which is the actual pain. Site chrome (nav, prev/next pagination) stays same-tab to keep the portfolio flow; reading (c) would make the home page's primary work cards open new tabs, which contradicts normal portfolio navigation.
- Consequences: the renderer needs an opt-in per call (e.g. `mdpage(src, { links: 'blank' })`); `scripts/test/mirror-link.test.js` must accept links carrying `target`; the teachr callout opens `../teachr-app/?view=library` in a new tab (still verified 200 under the mirror).
