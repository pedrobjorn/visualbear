# DR-0001: Sticky section nav takes the header's background color, not the page ground

- Date: 2026-11-23
- Status: accepted (pending Pedro's visual confirm at build time)
- Context: Pedro's request says "on scroll have stick to the header matching the background color". Two readings: (a) the stuck bar's background = the header's background, so bar + header read as one continuous block; (b) the bar's background = the page ground, so content scrolling under it is hidden by a page-colored plate. The header colors already exist per page as body-class rules: default `$vb-primary` #d73735, `body.cs-pink-page` #d50e95, `body.cs-black-page` #111111, `body.cs-teal-page` #0e7d6f (src/_styles/templates/_case-study.scss:1250/1319/1523, nav.scss:10).
- Decision: (a). One custom property `--cs-head-bg` is set on `body` (default #d73735) and overridden in the existing `body.cs-*-page` rules; both `nav.site-nav` and `.cs-index` consume `background-color: var(--cs-head-bg)`. The stuck bar is therefore pixel-identical to the header by construction, with a hairline bottom border in the theme accent for separation.
- Rationale: "matching the background color" attaches to "the header" the bar sticks to; a single variable keeps nav and bar identical on all four pages with zero per-page duplication; a page-ground bar would stack a second color band directly under the header on every theme.
- Consequences: when stuck, header (48px) + bar read as one block; `.cs-index` link ink is white like the nav links on the same grounds (the nav already passes the review gates with white links on these four colors), active link gets underline + lifted accent; `.cs-index` must be opaque so content scrolling under it is hidden; z-index 1, under the nav's z-index 2.
