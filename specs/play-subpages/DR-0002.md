# DR-0002: Photogallery content comes from a build-time folder scan, newest file at the top left

- Date: 2026-11-14
- Status: accepted (Pedro's rule 2026-11-14: "new images added to folder automatically create a new card at the top left")
- Context: every other gallery on the site is driven by a hand-maintained JSON in `src/_data/` (`work.json`, `play.json`, `blog.json`). The photogallery requirement is explicitly automatic: drop an image in a folder, rebuild, and a new card appears at the top left.
- Options weighed: (a) manual `photogallery.json` like the other galleries - rejected, it is not automatic and duplicates the folder; (b) the nunjucks gulp task scans `src/_images/play/photography/` at build time, sorts by file mtime descending, and injects the result as `site.data.photogallery` - chosen.
- Decision: (b). `gulp/nunjucks.js` (after the existing foldero load of `src/_data/`) reads `src/_images/play/photography/*.{jpg,jpeg,png,webp}`, sorts newest mtime first, and sets `siteData.photogallery = [{ file, title, img }]` where `title` is the basename without extension with `-`/`_` humanized to spaces, and `img` is the bare filename (the page prefixes `../../images/play/photography/`). Missing folder = empty array, no error.
- Rationale: same stack (the task already uses `fs`/`path` for data loading), zero new dependencies, and "newest first" maps directly onto mtime so a freshly dropped photo lands top-left as required. The existing `copy` + `imagemin` tasks already ship that folder to `images/play/photography/`.
- Consequences: adding an image must re-run the nunjucks task - Ticket 4 adds the folder to the dev watcher in `gulp/watch.js` (the production watch already full-rebuilds via `sync-mirror`). Retitling a photo in the lightbox = renaming the file. The lightbox caption uses the same humanized filename (open question in the plan if Pedro wants a sidecar instead).
