# DR-0004: Anchoring stays on the CSS mechanism; coverage is completed to every real anchor target instead of re-adding the retired JS interceptor

- Date: 2026-11-17
- Status: accepted (pending build)
- Context: ticket 24 (commit 7d99707) retired the `initSmoothScroll` JS intercept/scrollTo chain from `src/_scripts/main.js` and moved same-page anchoring to the platform: `html { scroll-behavior: smooth }` with a `prefers-reduced-motion` opt-out, plus `scroll-margin-top: 48px` on an explicit id list in `src/_styles/atoms/_base.scss`. That list (`#work #about #contact #core #modules #containers #casesystem`) predates the play sub-pages and the art-ent section links, so targets like `#play`, `#discovery`, `#definition`, `#iteration`, `#implementation`, `#visual` land underneath the fixed 48px nav. Pedro asks to re-add smooth scroll-to anchoring across all experience.
- Options weighed: (a) re-add the JS interceptor - rejected, ticket 24 deliberately delegated to CSS because `scroll-behavior: smooth` also covers cross-document fragment navigation (`../#work` from `/about/`), which the old pathname comparison handled only for same-document clicks; the CSS route is strictly broader; (b) a global `[id] { scroll-margin-top: 48px }` - rejected (recorded in the existing comment), it would paint a margin on every id on the site; (c) keep the explicit list and extend it from a full anchor audit - chosen.
- Decision: extend the `scroll-margin-top: 48px` selector list in `_base.scss` with `#play`, `#discovery`, `#definition`, `#iteration`, `#implementation` (audit in plan.md). Dead fragments stay out: `#visual` (styleguide demo links with no target id) and `#templates` (inside an HTML comment) - the audit test scripts/test/anchors.test.js enforces "every live target covered, dead fragments excluded". No JS changes. `scroll-behavior: smooth` + the reduced-motion opt-out stay global on `html`, which already covers every page since all pages extend `_layouts/base.nunjucks`.
- Rationale: the mechanism was never missing; the target list was incomplete. Completing the list restores correct anchoring on `/play/`, `/art-ent/`, `/climate-clock/`, and the styleguide demo links without reintroducing JS.
- Consequences: any new anchor target added to a page must be added to the list (same rule as ticket 24). Verification is browser-based: every audited anchor must land its target at `getBoundingClientRect().top == 48` (+-1px) with `scroll-behavior: smooth` computed, and land identically with `auto` under reduced-motion emulation.
