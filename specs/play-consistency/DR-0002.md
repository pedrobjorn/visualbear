# DR-0002: One dark gradient for the whole `/play/` section, via a single `body.page-play` class

- Date: 2026-11-17
- Status: accepted (pending build)
- Context: `/play/` paints the default red body gradient, `/play/blog/` + posts paint the red brand fade layer (`body.page-blog`, DR-0007), `/play/photography/` paints its own dark grey gradient (`body.page-photography`, DR-0006: flat `#18181b` base + one viewport-tall `::before` layer fading `#3a3a41 0%` to `#18181b 100%` in oklab). Three grounds under one section; Pedro wants blog + play gallery pages consistent, 1 gradient, dark.
- Options weighed: (a) invent a new dark gradient for blog/play - rejected, photography's dark gradient is already measured and shipped, reusing its exact values means zero visual change on photography and one definition to maintain; (b) keep the page-anchored `::before` layer pattern from ticket 52/DR-0007 - chosen, the layer is what prevents the canvas-propagated gradient from re-tiling every viewport height on long pages; (c) paint the gradient on `body` directly - rejected, same tiling defect DR-0007 fixed for blog.
- Decision: in `src/_styles/atoms/_base.scss`, add one shared rule `body.page-play` with `background: #18181b` and the `::before` layer `linear-gradient(180deg in oklab, #3a3a41 0%, #18181b 100%)` at `100vh/100svh`, z-index -1; remove `body.page-blog` from the home-fade selector (home stays `body.home-page` only) and delete the old `body.page-photography` rule. Set `{% block bodyattrs %} class="page-play"` on `/play/`, `/play/blog/`, all four blog post pages, and `/play/photography/`.
- Rationale: one selector, one gradient, one layer pattern; photography's measured values become the section standard so no existing play page changes except blog/play-index, which move from red to dark per the request. The hero organism is transparent with `$vb-light` text, so it reads unchanged on the dark ground.
- Consequences: this supersedes the background portions of play-subpages DR-0006 (photography's private gradient) and DR-0007 (blog's red fade layer). Any future page under `/play/` sets `class="page-play"` in bodyattrs. The fixed nav otherwise paints solid brand red (`nav.scss` base rule), which would cap a dark page with a red bar, so `body.page-play nav.site-nav` takes the gradient's top stop `#3a3a41` (verified by pixel probe: zero red pixels in the 48px nav band on all play pages). Likewise the gallery's fade plate is re-colored, not dropped: `body.page-play .content.gallery { background: linear-gradient(to bottom, rgba(24,24,27,0) 256px, rgba(24,24,27,1) 0px) }`. The plate is load-bearing - it masks the fixed hero title behind the gallery on scroll (verified: 0/1276 hero-visible points at scroll 900, same as home) - and in the page color it matches the ground at every scroll position (Pedro's follow-ups 2026-11-17: the `#252528` plate contrasted, `background: none` let the title bleed through). Mobile keeps `background: none`. Home keeps its `#252528` plate since home's flat base is `#252528`. The `.photoview-btn` background consequence is handled in DR-0003. Home and all non-play pages keep the red brand fade untouched.
