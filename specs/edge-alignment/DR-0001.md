# DR-0001: one page column - body content aligns to the nav's `.content` box on all devices, all public pages

- Date: 2026-11-15
- Status: accepted (Pedro's request 2026-11-15: "make the body content on all
  devices match the edges of the logo / navigation buttons"; when asked which
  edges, Pedro chose "nav container edges"; scope "all public pages")
- Context: measured on the 2026-11-15 build - the nav's `.content` box
  (max-width 916, margin auto, full-bleed below 916) spans 262..1178 at 1440
  and 0..390 at 390, with the logo box at 260..304 (desktop) / 6..50 (mobile)
  and the last nav link box flush to the right edge. Body containers sat
  narrower: `.content.gallery` / `.text-box` / `.text-container` capped at
  900px (8px narrower per side on desktop), gallery cards inset another 14.4px
  col gutter, case-study text-box padded 32px desktop / 36px below 907px.
  Measured text edges: home card text 300.4 @1440 / 30.4 @390; workflow text
  302..1138 @1440 / 36..354 @390; resume 316..1123 @1440 / 33.9..356 @390 -
  all inside the menu elements' edges.
- Decision: the page column is the nav's `.content` box, everywhere.
  1. All body container caps move from 900px to the nav's 916px (single
     `$content-width: 916px` variable in `_variables.scss` so there is one
     place to change): `.content.gallery`, `.photoview-title`,
     `.photoview-switch`, `.text-box`, `.text-container`, `.gallery-text`
     caps in `_gallery.scss`, `_textelements.scss`, `_typography.scss`,
     `gallery.scss`.
  2. Gallery card columns drop their 14.4px gutter inside `.content.gallery`
     so card boxes span the full page column (cards keep their own 16px
     inner padding - same relationship the nav links have to the nav box:
     elements reach the container edges, text keeps an inner gutter).
  3. Small screens (below 916px viewport, where the column is full-bleed):
     the case-study text-box gutter drops 36px -> 16px (and the styleguide
     demo wrapper likewise), so body text lands at 16..vw-16 - the same edge
     the last nav link's label reaches (16px padding-right) on mobile.
     Desktop text gutter stays 32px.
- Rationale: Pedro picked the nav container edges as the target. Aligning the
  containers (not the glyphs) is what "the menu elements" do: the logo and
  link boxes reach the container edges while their content keeps padding.
  Matching that pattern keeps text readable (no 0px gutters) while removing
  the visible "narrower than the menu" step.
- Consequences: the documented content width changes 900 -> 916 (text
  measure 836 -> 852 at 32px gutter), so the styleguide "Width tiers" copy
  and the DR-0013/DR-0009 references to 900/836 are updated in the docs
  ticket. The resume-page "no styling changes" rule from
  specs/resume-cv/DR-0003 was scoped to that spec's tickets; this request
  explicitly overrides it for /resume/'s container width.
