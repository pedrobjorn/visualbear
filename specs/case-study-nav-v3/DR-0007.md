# DR-0007: the cs-index section nav extends to the three sectioned legacy case-study pages (art-ent, climate-clock, steam-mobile)

- Date: 2026-11-24
- Status: accepted
- Supersedes: -
- Context: Pedro 2026-11-24: "Apply the same navigation structure and decisions to other case studies." The five md-driven case studies (fashion-rebrand, sports-ecommerce-redesign, digital-closet, teachr, teachr-agent) share the nav via the `.case-study` shell + `mdtoc`. The remaining case-study pages are hardcoded nunjucks: art-ent, climate-clock, steam-mobile have section structure (adhops and projectile-lynx have none - hero + images + one paragraph - so no nav there; confirmed with Pedro: "3 sectioned legacy pages"). Their full md migration is the phase-4 backlog (specs/md-case-study-editor), NOT this ticket. The decisions to apply are DR-0005 (full-bleed bar; link row limited to the 916px content container, centered) and DR-0006 (natural-width options, `space-between`, first/last touch the row edges, simple labels, nothing cut off), plus the v2 mechanics (sticky top 48, z-index 1, `--cs-head-bg` bar matching the header, 35px `--cs-index-h`, scroll-margin landing below the stuck bar).
- Decision: add the `case-study` class to the three legacy `<article>`s and insert the same `<nav class="cs-index" aria-label="Case study sections"><ul><li><a class="btn" href="#id" title="Label">Label</a></li>...</ul></nav>` markup (byte-format identical to mdToc's output, so the phase-4 md migration can drop in later) directly after the hero, before the first content section. All other `.case-study` rules target `.cs-*` classes the legacy pages do not use - except the bare `.case-study h1 { margin: 0 }`, which is re-scoped under `.cs-hero` so legacy hero h1s (headline molecule, not in a `.cs-hero`) keep their margins; the five md pages are unaffected because their h1 lives in `.cs-hero`. Nav targets get the section ids (added where missing) plus a `cs-nav-target` class, and one new rule `.case-study .cs-nav-target { scroll-margin-top: calc(48px + var(--cs-index-h, 40px)) }` mirrors the `.cs-section` landing rule. Bar bg comes from `body`'s default `--cs-head-bg` ($vb-primary), so the bar matches the default red header on these pages, same as the md pages' theme tokens. Nav lists (simple terms, max 5, DR-0006): art-ent = Discover#discovery, Define#definition, Iterate#iteration, Implement#implementation, Conclusion#conclusion (id added); climate-clock = Overview#definition, Branding#iteration (existing first id; the duplicate id="iteration" at the "The site" block stays untouched - not a nav target), Site#site, Display#display, Lessons#lessons (ids added); steam-mobile = Process#process, Research#research, Identity#identity, Results#results, Lessons#lessons (ids added to the h1 containers).
- Rationale: same navigation structure and decisions on every case-study page, with zero restyling of the legacy pages: the only `.case-study` selectors that can hit them are the `.cs-index` block and (formerly) the bare `h1`, which is now scoped under `.cs-hero`. Hardcoded nav markup keeps the pages buildable today and identical in shape to mdToc output for the later migration.
- Consequences: `src/{art-ent,climate-clock,steam-mobile}/index.nunjucks` gain the `case-study` class, the nav markup, and target ids + `cs-nav-target`; `_case-study.scss` moves `h1 { margin: 0 }` into `.cs-hero` and adds the `.cs-nav-target` scroll-margin rule; `cs-nav.test.js` gains a legacy-pages block (article class, nav markup after the hero, exact label|id lists, target ids + class present, scss assertions). Playwright AC on the 3 pages at 1440/768/390: bar full-bleed 0..viewport, ul == 916px container centered (262/1178 at 1440, full width below 900), first/last anchors flush to the row edges within 0.5px, no anchor clipped at any width, li flex-grow 0, bar height 35, stuck top 48 + bg == header bg, nav is the hero's next sibling, clicking a nav link lands the target at top >= 83px (48 + 35), page scrollWidth <= viewport at 390.
