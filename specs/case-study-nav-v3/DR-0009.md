# DR-0009: active nav anchor = text underline only; the `--cs-index-active` line is removed

- Date: 2026-11-24
- Status: accepted
- Supersedes: the line half of DR-0008 (the underline half of DR-0008 stands; DR-0002's original underline-only active state is restored)
- Amends: DR-0008
- Context: Pedro 2026-11-24, after seeing the shipped Ticket 3 active state: "fix the underline on scroll: just use the text underline, don't add a random red line below the focused section". The 3px inset `box-shadow` line under the active anchor reads as a stray red/white stripe on the bar's bottom edge, not as an underline.
- Decision: `a[aria-current='true']` = `text-decoration: underline; text-underline-offset: 4px;` — identical to the hover/focus recipe, no `box-shadow`. The `--cs-index-active` token, its `.case-study` default, and the three themed `body.cs-*-page .case-study` overrides are removed entirely (no dead tokens). The scroll-spy (`cs-index.js`) is unchanged: it still sets exactly one `aria-current="true"` on all 8 pages; only the visual rendering of that attribute changes.
- Rationale: one active-state recipe (underline) instead of two stacked cues; keeps the ghost button (no fill, no line); matches the header links' underline feedback, so the bar reads as chrome-consistent. The underline alone still satisfies WCAG 1.4.1 (text decoration, not color-only).
- Consequences: `_case-study.scss` loses the token decl, the themed override block, and the `box-shadow` line; the `a[aria-current='true']` rule keeps underline + offset. `cs-nav.test.js` Ticket 3 block now asserts the token is ABSENT, the aria-current rule has `text-decoration: underline`, and has NO `box-shadow`. Playwright re-verified on all 8 pages x 1440/768/390: scrolled into a section -> exactly one aria-current with correct href, computed `text-decoration-line: underline`, computed `box-shadow: none`; top -> zero aria-current; click sets it immediately. Evidence: `evidence/t3b-verify.md`.
