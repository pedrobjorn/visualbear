# DR-0008: active nav anchor gets the 3px `--cs-index-active` line AND an underline; the spy extends to the legacy case studies (8 pages)

- Date: 2026-11-24
- Status: amended by DR-0009 same day — the underline half shipped and stands; the 3px line half was reverted by DR-0009 ("don't add a random red line below the focused section")
- Supersedes: -
- Amends: DR-0002 (active state) and DR-0007 (legacy pages)
- Context: Pedro 2026-11-24, on top of Ticket 3: "also consider having the anchor underlined when in the section". DR-0002 shipped-planned the active state as the inset line with `text-decoration: none`; the underline is the v2 dead rule's behavior, now wanted back IN ADDITION to the line - hover/focus keep the plain white underline, the line is what distinguishes active. Also, DR-0007 put `.cs-index` on the 3 legacy pages (art-ent, climate-clock, steam-mobile) whose sections are `.cs-nav-target` containers, not `.cs-section` - the spy must observe both. Token placement note: the default `--cs-head-bg` is brand red on plain `body` (nav.scss), and the red-bar pages are exactly the un-themed ones (digital-closet + the 3 legacy pages), so the line token defaults to WHITE on `.case-study` and the themed body classes (pink/black/teal) override it to `$vb-primary` - the inverse of DR-0002's first sketch, same visible result (red line on teal/black/pink, white line on red).
- Decision: `a[aria-current='true']` = `box-shadow: inset 0 -3px 0 var(--cs-index-active); text-decoration: underline; text-underline-offset: 4px;`. Token: `.case-study { --cs-index-active: #fff; }` next to `--cs-accent`; `body.cs-pink-page .case-study, body.cs-black-page .case-study, body.cs-teal-page .case-study { --cs-index-active: #{$vb-primary}; }` beside the existing `body.<class> { --cs-head-bg }` theme blocks. Spy (`src/_scripts/cs-index.js`, booted from main.js, no-op without `.cs-index`): IntersectionObserver over `.case-study .cs-section, .case-study .cs-nav-target` with `rootMargin: -48px 0px -<barH>px 0px` where barH is read from the `.case-study` computed `--cs-index-h`; exactly one `aria-current="true"` on the matching `.cs-index a[href="#id"]` (topmost intersecting section wins); none when no section intersects (hero zone); set immediately on anchor click too. Works identically on the 5 md pages and the 3 legacy pages (8 total).
- Rationale: underline + line is the strongest non-fill active state that keeps the ghost button recipe (v2 DR-0005); line alone was DR-0002, Pedro asked for the underline on top. White-default token mirrors how `--cs-head-bg` already defaults on body, so red bars (default body) get a visible white line with zero extra selectors on those pages.
- Consequences: `src/_scripts/cs-index.js` (new) + one require/init line in `main.js`; `_case-study.scss` gains the token, the 3 themed overrides, and the rewritten `a[aria-current='true']` rule; `cs-nav.test.js` asserts the token + overrides, the rule (`var(--cs-index-active)`, `inset 0 -3px`, underline present, `text-decoration: none` absent for aria-current), and the spy source (observes `.cs-section, .cs-nav-target`, IntersectionObserver, reads `--cs-index-h`, wired from main.js, no cs-index in blog/workflow templates). Playwright AC on all 8 pages at 1440/768/390: scrolled into a section -> exactly one aria-current, correct href, computed box-shadow contains the active color, `text-decoration-line: underline`; page top -> zero aria-current; red-bar pages (digital-closet, art-ent, climate-clock, steam-mobile) resolve `--cs-index-active` to #ffffff; themed pages (teachr, fashion-rebrand, sports-ecommerce-redesign, teachr-agent) to #d73735; click sets aria-current immediately.
