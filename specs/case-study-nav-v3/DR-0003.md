# DR-0003: Nav labels are condensed per page via explicit `nav:` lists, capped in length at the authoring gate

- Date: 2026-11-24
- Status: accepted (cap value 24 chars and the exact proposed labels are ASSUMPTIONS - owner Pedro, plan Open questions)
- Context: Pedro 2026-11-24: "Condense some options, like 'Future improvements, Based on learnings' so they are not super long links." Measured 2026-11-24: fashion-rebrand's fallback label "Future Improvements, Based on Learnings" renders as a 362px link (the longest on any page); sports' whole row is 1052px, already wider than the 884px content column at 1440 before DR-0001 shrinks the bar; teachr's configured "Deepdive: Teachr Assistant" is 238px / 27 chars. The fallback (v2 Ticket 1) uses the full `##` primary title as the label, which is where the long strings come from.
- Decision:
  1. Every case-study page gets an explicit `nav:` list (label | id, max 5, existing v2 machinery: draft `Nav:` head lines -> `draft-to-md.js` -> page md front matter -> `mdToc`; ids validated against `##` ids, >5 throws). Proposed condensed lists (first-5 sections, shortened labels; Pedro confirms/edits):
     - fashion-rebrand: Context#context, Deep-Dive#deep-dive, Process#process, Outcomes#outcomes, Future & Learnings#future
     - sports-ecommerce-redesign: Problems#definition, Brand & Process#exploration, Site Redesign#site-redesign, Rollout#site-delivery, Outcome#site-outcome
     - digital-closet: Problem#definition, Research#research, Flows & Validation#discovery, Design System#delivery, Outcome#outcome
     - teachr-agent: Outcomes#outcomes, Process#process, Problem#problem, Research#research, Discovery#discovery
     - teachr keeps its v2 list; open question whether "Deepdive: Teachr Assistant" condenses to "Assistant".
  2. Authoring gate: `verify-page-md.js` rejects a `nav:` label longer than 24 characters (ASSUMPTION - one-value change; 24 chars at 14px uppercase is roughly 200px, inside a ~177px equal-width button only with ellipsis, which is why DR-0001 adds the `title` attribute). `mdToc` stays lenient at runtime (throws only on >5 entries / unknown id, as in v2); the strictness lives in the gate + `cs-nav.test.js`, not the renderer, so a long label fails the build check rather than a user's page.
- Rationale: labels are nav chrome, not headings; the full section title remains in the section's own `h2` and in the anchor's `title`. Explicit per-page lists (not an automatic truncation rule) because Pedro's own teachr list mixes custom phrasing that no rule derives - same reasoning as v2 DR-0001. The cap prevents regression: a future long title cannot silently become a 362px link again.
- Consequences: 4 drafts gain `Nav:` lines and their page mds regenerate via text-to-md (round-trip verified); `verify-page-md.js` gate 1b gains the label-length rule; `cs-nav.test.js` asserts the exact per-page label lists and a synthetic >24-char label failing the gate (unit-level, gate function called directly); AUTHORING.md's `nav:` contract documents the cap.
