# DR-0004: Showcase tier is read from the image itself; wide goes full-bleed, tall goes narrow

- Date: 2026-11-09
- Status: accepted
- Context: Case-study images previously rendered at one size (the text measure, or placeholders). The Quizrr page mixes three kinds of asset — page-wide desktop strips, phone-portrait captures, and small pop-out details — and one size fits none of them: wide strips cramped, phone captures blown up huge.
- Decision: The showcase figure picks its tier from the asset's own pixels, read at render time by `markdown-render.js` (PNG IHHR/JPEG SOF/GIF header parse, no deps):
  - `cs-showcase--wide` — ratio ≥ 1.4 and ≥ 1800px natural width → full-bleed, edge to viewport edge (same breakout as `.cs-wide--full`);
  - `cs-showcase--tall` — ratio ≤ 0.75 and ≤ 1200px natural width → narrow (480px), centred, generous margins;
  - default → the text measure, now with real breathing room (40–48px vertical margins).
    The draft author never marks the tier — an image moves tiers just by being replaced with a wider or taller export.
- Rationale: Authors drag in whatever the design tool exports; asking them to tag `| wide | tall` duplicates information the file already carries and drifts. Dimension-based tiers keep phones at phone scale and desktops at page scale automatically.
- Consequences: Sizing is invisible at draft-txt level (deliberately); to force a different tier, export the asset at a different size — or, if a legitimate case appears, extend the rule thresholds, not the syntax. Screenshots for the review report come from these tiers.
