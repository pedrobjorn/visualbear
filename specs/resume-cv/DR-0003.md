# DR-0003: strict rule - pasted CV copy is verbatim and resume styling is untouched; "adapt" means structural mapping only

- Date: 2026-11-15
- Status: accepted (Pedro's instruction, 2026-11-15: "DO NOT CHANGE THE COPY I
  ADDED OR THE STYLING IN THE RESUME. Simply take what was pasted and adapt it
  to the Resume")
- Context: the 2026-11-15 CV was pasted as the copy source. Earlier tickets
  left small copy freedoms open (fix the "webb" typo? drop the stray "Key
  Achievements" heading over the degrees? reword anything that reads oddly?).
  Pedro closed all of them at once.
- Decision: (1) every string in the pasted CV is verbatim in the build - no
  typo fixes, no rewording, no repunctuation, no reordering inside a pasted
  block, no joining/splitting of pasted lines; (2) no styling changes to the
  resume - no `.scss`/`.css` edits, no new classes, no inline styles, markup
  additions reuse existing classes only; (3) "adapt it to the Resume" is
  defined as structural mapping only: pasted content is placed into the
  existing constructs (title block + `mdresume` sections). Anything that would
  edit or drop a pasted string is raised as an open question to Pedro, never
  silently resolved.
- Rationale: the CV is Pedro's own published words; silent edits (even
  well-meant typo fixes) would misattribute his voice, and style drift on a
  page he owns is his call. Encoding the rule in the spec keeps the executing
  agent from "improving" anything.
- Consequences: supersedes any reading of DR-0001 that allowed dropping or
  renaming a pasted string (the degrees still map to the `## Education |`
  section - placement, not copy). The "webb" typo ships verbatim. Ticket 6
  gains two machine-checkable gates: a byte-for-byte presence check of every
  pasted string in the built HTML, and an empty `.scss`/`.css` diff check.
