# DR-0004: Pedro explicitly authorized one styling change - red bullets on the Core Skills list (supersedes strict rule 2 for this item only)

- Date: 2026-11-15
- Status: accepted (Pedro's instruction, 2026-11-15: "Add the red bullets to the
  core skills bullets")
- Context: DR-0003's strict rule 2 says "DO NOT CHANGE THE STYLING IN THE
  RESUME". The next instruction from Pedro asks for a styling change, so the
  rule is superseded for exactly this item; every other styling surface stays
  untouched.
- Decision: the Core Skills leaf items (the nested `ul.no-bullets` inside the
  skills tree) get the resume's standard content-list dot treatment - 5px
  round `::before` in the resume's link red `#d0181e` - by extending the
  existing `ul:not(.no-bullets)` rule in `_resume.scss` with the nested
  selector `ul.no-bullets ul.no-bullets`. No new values, no new properties:
  the dot reuses the exact treatment the Key Responsibilities / Key
  Achievements / Education / Languages lists already have.
- Rationale: "red bullets" on a resume whose other lists already carry red
  dots means the same red (`#d0181e`, the accent family of this page), not the
  brighter brand `$vb-primary`. Reusing the existing rule keeps one dot
  treatment on the page instead of introducing a second one.
- Consequences: group titles (Technical / Product Design / Design Leadership,
  rendered as `h3.sub-title` inside the parent no-bullets list) stay unmarked;
  only the leaf skill items get dots. Copy is untouched (strict rule 1 still
  holds in full).
