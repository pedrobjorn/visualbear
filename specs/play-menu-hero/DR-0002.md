# DR-0002: Photography adopts the shared hero organism so the Blog and Photos pages match structurally

- Date: 2026-11-17
- Status: accepted (pending build)
- Context: `/play/blog/` is hero organism + 66vh-spaced gallery in a 900px column. `/play/photography/` has no hero: a bare `h1.photoview-title` on the 900px line, the sticky switch, and a full-bleed grid with `margin-top: 0`. Pedro wants the Blog and Photo heroes and pages to match, with a bit more space for Photos and less for the Blog.
- Options weighed: (a) give photography the hero organism (`hero.content` with a new `photohero.yml`, title "Photography") and delete the standalone `.photoview-title` h1 - chosen; (b) remove blog's hero and make both bare - rejected, that regresses the blog page and the h1-per-page rule; (c) keep both layouts and only match colors - rejected, "heros and pages match" asks for structure, and colors already match via `body.page-play` (play-consistency DR-0002).
- Decision: add `src/_data/photohero.yml` (`name: photo`, `title: Photography`); in `src/play/photography/index.nunjucks` render `{{hero.content({content:site.data.photohero, class:'hero--roomy hero--center'})}}` before `.photoview`, remove the `<h1 class="photoview-title">` and `.photoview`'s `padding-top: 48px` (the hero occupies the top now; the switch stays `sticky; top: 48px` under the fixed nav). On desktop the photogrid container needs the hero-clearing spacer that `:has(.gallery-grid)` currently zeroes: `body.play-photos .content.gallery:has(.gallery-grid) { margin-top: <spacer>vh }`. Delete the now-unused `.photoview-title` rule from `gallery.scss`. Blog pages get `class="page-play play-blog"` (index + 4 posts) and the blog hero gets `hero--snug`.
- Rationale: one page skeleton for the whole `/play/` section (hero + content), which is what "pages match" means; the hero h1 keeps exactly one h1 per page; the fixed hero needs the spacer or the full-bleed grid would slide under it (the peek defect play-consistency fixed with the plate).
- Consequences: hero height modifiers (`hero--roomy` 48vh / `hero--snug` 32vh, values are an ASSUMPTION in plan.md) must be declared BEFORE the mobile media query in hero.scss so the mobile `height: auto` still wins; mobile needs no spacer (hero is static there, and the mobile gallery rule already sets `margin-top: 0`). The `.photoview-switch` remains sticky below the nav on both breakpoints.
