# DR-0002: visuai-text-to-md is a rule executor, determinism is proven by goldens

- Date: 2026-11-02
- Status: accepted
- Context: requirement — "if I write two case studies that are near
  identical structurally the outcome should be identical". An LLM
  freely choosing markdown constructs will drift between runs and
  between similar inputs; a pure deterministic script cannot interpret
  messy free-form input.

## Decision

The skill is a rule executor with an LLM reader, in this fixed shape:

1. **Segment** the source text on mechanical boundaries (blank lines,
   heading-like lines, list markers) - no interpretation.
2. **Classify** each block against a FIXED precedence table shipped in
   the skill (highest wins, ties break to the plainest construct):
   metrics-like `value | label` lines → `::: metrics`; before/after
   pairs → `::: compare`; quoted lines → `>` quote; explicit step
   language → numbered timeline; caption-after-image → `[point:]`;
   fact-list signals → `-` chips; anything unrecognized → plain
   paragraph + `<!-- TODO: confirm construct -->`. The table may only
   change via a spec change and a golden-suite update.
3. **Emit** through fixed per-construct templates (spacing, heading
   order, two-blank-line rules per AUTHORING.md), then canonicalize:
   prettier-format, normalize directive spacing, strip trailing
   whitespace, enforce the em-dash rule.
4. **Verify** with the bundled gates (`format:check`, `doc-sync.sh`,
   em-dash check, image-ref existence) and report pass/fail.

Hard rules: the skill never drops source content (unmapped text
surfaces as TODO, never silence); **modifies structure only, never
content** (resolved with Pedro 2026-11-02: pasted text is final copy -
no rewording, reordering, summarizing or expanding unless Pedro
explicitly instructs it in the run; any copy produced on such an
instruction gets `[ai]` per DR-0008); never removes existing `[ai]`
markers; is idempotent (re-running on an edited md is refused with a
diff summary unless explicitly forced).

**Proof**: a golden-file suite in the skill - input texts plus
expected outputs; the determinism gate is that re-running the skill on
each input reproduces the golden byte-for-byte. Two structurally near
identical inputs differing only in names/dates/copy must produce
outputs identical modulo those substitutions. The suite is the
regression net whenever the precedence table evolves.

## Rationale

Determinism cannot come from model behavior; it comes from shrinking
the decision space (precedence table + plainest-construct tiebreak +
fixed templates + canonicalizer) and _testing_ the claim with goldens
rather than asserting it. This mirrors how the repo already works:
AUTHORING.md is a contract checked by a script, not a convention held
in anyone's head.

## Consequences

- Exotic layouts the signals don't cover need either a new precedence
  rule (with a golden) or hand-editing after conversion - by design.
- The goldens are load-bearing: they must run as part of the skill's
  definition of done, not as optional docs.
- Skill behavior changes are versioned by the golden diffs, giving an
  audit trail for "why did my conversion change".
