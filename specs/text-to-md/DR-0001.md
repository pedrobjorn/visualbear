# DR-0001: Hero moves into page markdown as front matter

- Date: 2026-11-02
- Status: accepted
- Context: the text-to-md workflow requires the hero to be part of the
  markdown process, but heroes (and hero-meta blocks: metrics, Needs
  card, related link) are hardcoded in each `src/<page>/index.nunjucks`
  shell with bespoke variants (`cs-hero--teal`, `--black`,
  `cs-hero--meta`; DR-0014). A conversion skill cannot produce the
  hero if the hero lives outside markdown.

## Decision

Page markdown in `src/_data/pages/` gains a front-matter block at the
top:

    ---
    hero:
      variant: teal        # cs-hero--<variant>; omit for the plain hero
      eyebrow: Case Study — Teachr (mock brand)
      title: Teachr, Redesigning the Learning Experience
      summary: >
        Revamping a teaching tool used by thousands of users...
      details: Lead Designer ⋅ Figjam · Figma · Claude Code ⋅ 2025 – 2026
      meta:                # the cs-hero--meta block, bounded vocabulary
        - logo: ../images/work/fullsize/teachr/teachr_logo.png
        - needs: Mock up a design system, and mock up the training flow...
        - related: ../teachr-agent/ | Teachr, AI Agent in the Learning Dashboard
        - metrics: 20k | new users per month*
        - footnote: "* for two pilot markets"
    ---

`mdpage` parses front matter and exposes it to the shell; the shell's
hero/header markup is generated from it (static-site data, not
runtime). `bodyattrs` variant classes derive from `hero.variant`.

## Rationale

- Keeps one source of truth per page: the `.md` file carries ALL page
  content including the hero, which is what the skill needs to emit.
- Front matter (not a `:::` block) because hero data feeds the shell
  (`<title>`, body class, `<head>`) — it must be data, not body HTML.
- Bounded `meta:` vocabulary (logo/needs/related/metrics/footnote)
  keeps the hero-meta variety of today's hand-written shells expressible
  without reopening free-form HTML in markdown. Resolved with Pedro
  2026-11-02: this full vocabulary ships from day one (ticket 1).
- DR-0014's shared hero component is untouched: same classes, same
  spacing; only the source of the markup moves.

## Consequences

- Every md-page shell changes once (tickets 1-2), verified pixel-identical
  per page with full-page diffs, per the repo's standing practice.
- `AUTHORING.md` gains a front-matter section; the doc-sync rule
  extends to it.
- Pages without front matter keep working exactly as today (backwards
  compatible; migration is per-page and opt-in until complete).
