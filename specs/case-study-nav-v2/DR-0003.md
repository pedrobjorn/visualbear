# DR-0003: Nav anchors are full-bar-height design-system buttons, not squeezed text links

- Date: 2026-11-24
- Status: accepted
- Context: Pedro 2026-11-24: "Make the clickable anchors as tall as the container, and make them follow the design system button. don't squeeze them inside a smaller container." Measured 2026-11-24: inside the 37px `.cs-index` bar, each `<a>` is 20px tall (font line) with Materialize's `nav ul a { padding: 0 15px }` - the clickable box is a small strip inside the bar. The design-system button is `.btn` (`src/_styles/atoms/_buttons.scss`): uppercase, weight 400, flat, `transition: background-color .3s, color .3s`, `padding: 16px 8px`, `text-align: center`; the shipped transparent link-buttons (`vb-btn`, `vb-btn-full` in the same file) add white ink, hover `background-color: $vb-primary` (#d73735), active/focus `background-color: $vb-secondary` (#79a6d2).
- Decision: `mdToc` emits each link as `<a class="btn" href="#id">Label</a>`; scoped under `.case-study .cs-index`: the `ul` becomes `display: flex; align-items: stretch; padding: 0` (DR-0002), `li` becomes `display: flex`, and the anchor gets `display: flex; align-items: center; height: 100%` plus the `.btn` recipe - transparent background (the bar's `--cs-head-bg` shows through), white ink, uppercase, `padding: 16px 8px`, the `.btn` transition; hover = `background-color: $vb-primary` + white; active/focus = `background-color: $vb-secondary` + white, with a visible focus outline so keyboard focus is never color-only. The bar's own vertical padding goes to 0, so the anchor's box IS the full bar height ("as tall as the container"): bar height = 16 + 20 (line) + 16 + 1 (border) = 53px, which re-pins `--cs-index-h` (was 37px) and keeps `scroll-margin-top: calc(48px + var(--cs-index-h))` correct. Specificity note: `.case-study .cs-index ul a` beats Materialize's `nav ul a`, killing the 15px padding and any float/height quirks; `height: auto` on `.cs-index` (parent Ticket 2) stays to beat Materialize's `nav { height: 56px }`.
- Rationale: "as tall as the container" is only achievable with zero bar-side vertical padding and stretched anchors - padding on the bar would always leave the anchor shorter than the bar. "Follow the design system button" means the `.btn` recipe verbatim (that is the only button system the site has); the transparent variant matches `vb-btn`/`vb-btn-full`, which are anchors styled as buttons exactly like these nav links. `aria-current="true"` keeps its underline on top of the button style (parent Ticket 4).
- Consequences: bar height changes 37px -> 53px (measured at build, then pinned); `--cs-index-h` updates and `scroll-margin-top` follows automatically; hover now paints brand red on every theme bar (teal/pink/black included) - that is the design-system recipe, flagged in plan Open questions; the white-on-`$vb-secondary` active/focus pair (~2.2:1) ships with the recipe plus a focus outline, flagged for the review gate; `cs-nav.test.js` asserts the `btn` class on every emitted anchor.
