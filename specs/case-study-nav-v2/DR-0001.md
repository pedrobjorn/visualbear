# DR-0001: The section nav is an explicit per-page list (max 5), starting at Outcomes - not a mirror of every `##` section

- Date: 2026-11-24
- Status: accepted (pending Pedro's lists for the other pages)
- Context: Pedro 2026-11-24: "Keep the links to a maximum of 5. For example Teachr only has these: Summary / Context / Discovery & Validation / Design & Delivery / Deepdive: Teachr Assistant." Follow-up same day: "Skip the summary as part of the links, start with outcomes." Today `mdToc` (markdown-render.js:1023, parent Ticket 1) emits one link per `##` section - teachr renders 15 (measured 2026-11-24), sports-ecommerce 10, fashion 6, digital-closet 5. Options considered: (a) cap automatically at first-5 `##` sections; (b) derive labels from eyebrows; (c) an explicit per-page `nav:` list in the page md front matter with `label | id` entries, hard-capped at 5.
- Decision: (c). Each case-study page md gets a `nav:` front-matter key - a list of `{ label, id }` (max 5). `mdToc` reads `splitFrontmatter(src).meta.nav`, validates every `id` against the parsed `##` sections (unknown id = test failure, so labels/links can never drift from sections), and renders exactly those links in config order. Teachr's list (Summary removed per Pedro's follow-up, starts at Outcomes):
  ```yaml
  nav:
    - label: 'Outcomes'
      id: outcomes
    - label: 'Context'
      id: process
    - label: 'Discovery & Validation'
      id: discovery
    - label: 'Design & Delivery'
      id: decisions
    - label: 'Deepdive: Teachr Assistant'
      id: assistant
  ```
  Pages without a `nav:` key fall back to the first 5 sections in document order, label = primary title (ASSUMPTION - Pedro supplies real lists). More than 5 entries fails `scripts/test/cs-nav.test.js`. The draft txt head gains `Nav: Label | id` lines (the copy source of truth), mapped to front matter by `specs/text-to-md/tools/draft-to-md.js` / `md-to-draft.js`; the bounded vocabulary in `verify-page-md.js` gains the `nav` top-level key.
- Rationale: Pedro's teachr list mixes custom labels ("Deepdive: Teachr Assistant") that neither titles nor eyebrows derive - only an explicit list expresses it. Front matter matches the existing `hero:` pattern (text-to-md DR-0001), so the nav config travels the same draft -> md path as the hero. The id validation keeps the parent Ticket 1 guarantee (nav hrefs can never drift from rendered section ids). The follow-up resolves the earlier Summary mapping question: there is no Summary link at all; the first link is the `outcomes` section.
- Consequences: `mdToc` output changes from "all sections" to "configured <= 5"; `cs-nav.test.js` count assertions change from section counts (6/10/5/15) to config counts; AUTHORING.md's "the nav follows the `##` lines automatically" line must be updated; teachr's nav drops from 15 links to 5, so the 390px horizontal-scroll case mostly disappears but the `overflow-x: auto` guard stays.
