# DR-0005: Nav anchors are ghost buttons, touching and centered, at 2/3 of the full-size button

- Date: 2026-11-24
- Status: accepted (2/3 arithmetic is an ASSUMPTION - one-value flip, see plan Open questions)
- Amends: DR-0003 (hover/active lose the painted fill), refines DR-0002 (the link GROUP centers; the BAR keeps its left edge on the body edge)
- Context: Pedro 2026-11-24 (follow-up): "Make the buttons ghost buttons - Make them touch eachother and center aligned - Don't make them so big, maybe 2/3 size." The design system's ghost recipe already exists on the same colored bars: `nav.scss` keeps header links `background-color: transparent` on hover/active with underline feedback (the header color varies per page, so no fixed fill), and `.photoview-btn` (gallery.scss:236) is the same ghost-on-a-plate pattern (transparent bg, muted ink, underline on hover/focus, lifted ink when active). Materialize's `.btn-flat` (the only flat variant) paints `rgba(0,0,0,.1)` on focus and fixes `height: 36px`/`line-height: 36px`, so it is NOT reused - the scoped ghost style is used instead, same as `.photoview-btn` does.
- Decision:
  1. Ghost: `.case-study .cs-index a.btn` keeps `background-color: transparent` (bar's `--cs-head-bg` shows through) and `box-shadow: none` in ALL states; ink stays white (clears 4.5:1 on all four header colors, same as the header links); feedback = `text-decoration: underline` + `text-underline-offset: 4px` on hover/focus, exactly like `nav.site-nav .links a` and `.photoview-btn`; `aria-current='true'` keeps underline + lifted accent. No `$vb-primary`/`$vb-secondary` fill anywhere on the bar (supersedes DR-0003's hover/active fills). Focus keeps a visible outline (`&:focus-visible { outline: 2px solid #fff; outline-offset: -2px }`) so keyboard focus is never color-only.
  2. Touching + centered: `.cs-index ul { padding: 0; gap: 0; justify-content: center; }` - buttons sit flush against each other (no 24px/16px gaps) and the group is centered in the full-bleed bar. The bar itself stays `width: 100vw` full-bleed, so its left edge is still the body's left edge (0) - DR-0002's bar-level criterion stands; the group-level criterion changes from "first link left = 0" to "first link left = (viewport - row width)/2".
  3. 2/3 size: scale the DR-0003 full-size button (padding 16px 8px + 20px line = 52px content, 53px bar) by 2/3 -> `padding: 7px 8px`, which gives 7 + 20 + 7 = 34px content and a 35px bar incl. the 1px border (34/52 = 65% ~= 2/3; exact 2/3 of 52 would be 34.7px, not achievable with integer px padding at line-height 20). Font stays 14px/20px (shrinking the label below 14px would hurt legibility for no visual gain - ASSUMPTION). Anchors remain `height: 100%` of the bar, so the clickable area is still the full bar height at the smaller size ("as tall as the container" preserved). `--cs-index-h` re-pins to the measured value (expected 35px) and `scroll-margin-top: calc(48px + var(--cs-index-h))` follows automatically.
- Rationale: ghost matches how every other control on the colored bars already behaves (header links, photoview switch), so the stuck bar reads as one continuous header + index block with no painted boxes; touching centered pills are the standard compact index pattern; 2/3 keeps the bar slim (35px vs 53px) while the hit area still spans the bar.
- Consequences: bar height 37px -> ~35px (`--cs-index-h` re-pinned at build); `cs-nav.test.js` CSS-contract block gains assertions for `gap: 0`, `justify-content: center`, transparent background on the anchor and underline hover; Playwright acceptance changes to: adjacent anchors (`link[i+1].left === link[i].right`), row centered, anchor height = bar - 1px, bar height = measured `--cs-index-h`, hover shows underline and NO background-color change.
