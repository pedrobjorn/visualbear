# DR-0002: The nav row's left edge aligns to the `<body>` element's left edge (x = 0)

- Date: 2026-11-24
- Status: accepted
- Context: Pedro 2026-11-24: "Align the left edge to the left edge of the body." Measured 2026-11-24 (Playwright, built teachr page): `document.body` left = 0 at 1440 and 390 (body margin/padding 0); `.cs-index` is already full-bleed (left = 0); but `.cs-index ul` has `padding: 0 48px` desktop / `0 24px` at <=767px (`_case-study.scss:167,200`), so the first link's left edge is 48 (1440) / 24 (390). Readings considered: (a) the body element's left edge = 0 - links flush to the viewport edge, matching the fixed header where the logo sits at x = 0; (b) the body text column (`.document-text`, left = 262 at 1440, 0 at 390).
- Decision: (a). `.cs-index ul` side padding becomes 0 at all widths; the first anchor's `getBoundingClientRect().left` must equal `document.body.getBoundingClientRect().left` (0) at 1440x900 and 390x844. The anchor's own button padding (`16px 8px`, DR-0003) provides the 8px inset of the label text, same as the header's logo block sits at x = 0 with its own internal padding.
- Rationale: "the body" is the body element; reading (a) also matches the header, where the leftmost element (logo) is flush at x = 0, so header and stuck bar read as one continuous block with the same left edge. Reading (b) would indent the bar differently from the header and re-introduce a side padding Pedro asked to remove. The flip to (b) is a one-value change (`padding-left: 262px`-equivalent via the container) if Pedro meant the text column.
- Consequences: `_case-study.scss:167` (`padding: 0 48px`) and the `:200` mobile `padding: 0 24px` are replaced by `padding: 0`; the 390px `overflow-x: auto` strip still starts at x = 0; no page-level horizontal scroll may be introduced (bar is already `width: 100vw` full-bleed).
