# DR-0014: Below the 916 column the .text-container keeps its 16px side padding - text never touches the bleed (amends DR-0013)

- Date: 2026-11-15
- Status: accepted (Pedro, 2026-11-15: "padding is missing from text-container on smaller breakpoints. There should never be text touching bleed")
- Context: DR-0013 removed the root `.text-container` side padding at ALL widths so its content spans the nav-wrapper box. Measured consequence (evidence/t41-post-change.json): at every viewport <= 916 the container is full-bleed, so with 0 padding its text sat at 0px from the viewport edge (content 0..vw at 916/768/600/390/320 on /styleguide/ and /resume/) - text touching the bleed, which DR-0002's standing rule forbids ("nothing but image bleeds touches the bleed").
- Decision: DR-0013's zero-padding applies only where the 916 column leaves at least the 16px page margin, i.e. viewport > 947 (947 = 916 + 2\*16 - 1). At viewport <= 947 the container keeps 16px side padding (the nav's page margin, DR-0002). The invariant is crisp: text-to-edge gap = max(column side margin, 16) >= 16px at every width.
  - > = 948: content spans the nav-wrapper box (262..1178 at 1440) - DR-0013 unchanged.
  - <= 947: content sits 16px inside the container box; where the box is full-bleed (<= 916) that is the nav's text line, 16px off the edge - never touching the bleed. (The 915 convention was an off-by-one: at exactly 916 the column equals the viewport and is full-bleed, which is also behind the old 12px scroll hole at 916.)
- Rules touched (side padding only; vertical rhythm untouched):
  1. `_textelements.scss`: root `.text-container` base stays 0 (beats the per-band 32px sides at >= 948); a following `@media (max-width: 947px)` rule restores 16px sides (later rule, same specificity, wins at <= 947).
  2. `tabs.scss` `[data-vb-panel='designsystem'] .text-container`: reverted to the original 16px at <= 915 (redundant with the root media below 948, kept as the original rule).
  3. `_resume.scss` `#resume_container .text-container`: id-level 0 base + id-level 16px inside `@media (max-width: 947px)` (id beats the root media at all widths, so it needs its own media copy).
  4. `_grid.scss` `.section .text-container` (0,2,0, beats the root rule): 480-767px band `128px 0` -> `128px 16px`; 320-480px band `128px 0` -> `128px 16px`. (Hero `.outer-container .inner-container .text-container` rules untouched - the hero keeps its own 16px via hero.scss.)
  5. `_case-study.scss` bleed caps: the ticket-41 `#styleguide_container` <= 971 block is removed (the restored padding absorbs the demo bleeds again below 948); the global DR-0009 bleed cap breakpoint moves 915 -> 971 (971 = 916 + 2\*28 - 1): the 28px bleed can cross the edge whenever column margin + container padding < 28, which is exactly vw <= 971 - this also closes the pre-existing 12px scroll hole at 916-939.
- Rationale: "never text touching bleed" is the invariant; the nav-wrapper's own text never comes within 16px of the edge either (nav.scss edge-text rule insets the last link 16px from the box edge). Aligning the container with the nav BOX (DR-0013) only holds where that box has at least the 16px margin (> 947); below that the nav's visible text line is 16px in, so the container padding matches the nav text, exactly as DR-0002 had it.
- Consequences: at <= 947 text measure is the column minus 32 (vw-32 when full-bleed, 884 in the 916 column); at >= 948 it is the nav-wrapper width (916). DR-0013 stands amended, not reverted.
- Non-goals: no change at >= 948 (DR-0013 alignment kept), no vertical padding changes, no markup, hero/nav/text-box/gallery untouched.
