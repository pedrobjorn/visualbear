# DR-0009: Mobile 360 - reclaim padding slack instead of shrinking the nav

- Date: 2026-11-13
- Status: accepted
- Context: Pedro's mobile eval (360-375, Firefox Android; evidence/mobile-eval-2026-11-13.md) reported header overflow on Firefox Android only. Measured on desktop engines the nav fits 360 EXACTLY: the Contact box's right edge stands on the viewport boundary at every width (320/360/375) - the flex pair always fills the bar edge-to-edge with the only slack (54px at 360) between logo and links. Nav ink is 19.2px, targets 48px tall. The only engine-divergent knob in the shipped CSS is the `-webkit-text-size-adjust: 1.5em` / `-ms-text-size-adjust: 1.5em` pair (invalid per CSS spec: only auto | none | <percentage>); Firefox for Android ships text-size-adjust support, Chrome drops the value - divergence is possible. On-device Firefox Android behavior was NOT reproducible in this harness (ASSUMPTION in the evidence file).
- Decision: fix the BUDGET, not the symptom. (1) Replace the text-size-adjust pair with one valid declaration, `text-size-adjust: 100%`, which disables platform font inflation on both Android engines. (2) Reclaim real slack at the <=tablet breakpoint: link side padding 12 -> 8px (and the logo's 12 -> 8px margin), leaving the 16px last-child page margin intact - roughly 28-32px of slack at 360, an order of magnitude above any engine rounding variance. (3) Do NOT shrink the nav font, the logo, or the 48px bar: those carry the site's optical identity and the 44px touch-target bar (review gate 1).
- Rationale: an exact-fit flex row fails on any sub-1% text-widening engine difference - by construction, on any device, for any future font or letter-spacing change. Padding slack is invisible (the links are already breathing), scales up to 320 as well, and the one-line text-size-adjust change removes the only nonstandard text knob the CSS ships. Shrinking labels trades the brand look for a bug that padding space costs nothing.
- Consequences: the <=tablet nav tolerates text inflation at 320-480. If on-device validation finds the Firefox Android overflow persists beyond -32px of inflation (unlikely), the fallback is capping nav font at 16px under ~400px - a per-breakpoint exception recorded here ahead of time.
