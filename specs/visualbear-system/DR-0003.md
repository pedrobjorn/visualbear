# DR-0003: The floating mirror link is a robot, explicitly layered above content

- Date: 2026-11-12
- Status: accepted
- Context: The mirror's floating link (injected by `scripts/release-mirror.js` → `visuaiLinkFor()` into every mirrored page) renders the 🐻 emoji at bottom-left of the viewport. Two problems: (a) a bear reads wrong in a product story about AI; (b) the link carries no `z-index`, so positioned layers with `z-index: 1` and an opaque plate - `.foot` (`footer.scss`), `#about` (`_pages.scss:188`) - paint over it while scrolling; the link disappears exactly when a visitor reaches the contact area. Options for (b): rely on DOM order (the link is last in `body`, and painting order favours it against other `z-index: auto` elements) vs. an explicit z-index.
- Decision: Swap the emoji to 🤖 (`\uD83E\uDD16` - verified surrogate pair, not the `\uD83D\uDC28` koala the r4 probe once used), rename `a.bear` → `a.robot`, set `title`/`aria-label` "The visualbear system", and add an explicit `z-index: 3` to the inline style.
- Rationale: DOM-order reliance is fragile - it silently loses to any current or future `z-index: 1` surface, which is the observed bug. `z-index: 3` sits above the nav's `2` and the content surfaces' `1`; the link is a fixed bottom-left corner element and structurally never overlaps the 48px nav row, so outranking the nav has no occlusion cost. Emoji-not-SVG matches how the bear shipped (the injector is a pure string transform, no asset pipeline involvement) and keeps Ticket 1 a one-file change.
- Consequences: The link floats above everything - anything that legitimately needs to cover the bottom-left corner must beat `z-index: 3` deliberately (and will now trip review gates instead of silently winning). If Pedro later wants a brand-consistent robot mark, that is a pending asset (plan, Asset requests), not a blocker.
