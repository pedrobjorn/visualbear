# DR-0002: The merged visualbear system page is mirror-only

- Date: 2026-11-12
- Status: accepted, conditional on Pedro confirming (plan open question 1)
- Context: The merged view pairs the visuAI content (application-sensitive, mirror-only since release 4.0) with the design system (public today at `/styleguide/`). One page cannot be half-air-locked. Options:
  1. Merged page is mirror-only; public `/styleguide/` is retired (Ticket 4).
  2. Merged page is public, with the visuAI tab's content stripped from the public build - per-tab gating.
  3. Keep two separate pages (not combined; rejected in the plan).
- Decision: Option 1 - the merged page lives only inside the mirror and ships through the `workflow` entry already in `SECRET_DIRS` (`scripts/release-mirror.js`).
- Rationale: Per-tab gating (option 2) hides markup in the shipped HTML, and a client-side tab pair makes the hidden pane one DOM-inspection away from the content the air-lock exists to withhold - DR-R4-0002's posture (gated content lives behind the lock, not inside it) applies unchanged. Option 1 keeps the strongest half's guarantee intact and matches the mirror's existing structure (the robot link already points at `/workflow/`).
- Consequences: The public site loses the styleguide exposure ("present my portfolio itself as part of my portfolio work" was the styleguide intro's stated purpose) - a real portfolio tradeoff Pedro owns; superseding this DR with a public-design-system variant (e.g. a slimmed public tab with the visuAI panel absent from the DOM) is permitted, and it rescopes Ticket 4. Supersedes nothing: DR-0007's visuAI-page scope is unchanged, the page is still `/workflow/`.
