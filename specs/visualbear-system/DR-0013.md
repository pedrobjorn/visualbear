# DR-0013: The root .text-container drops its side padding - its content spans the nav-wrapper's width

- Date: 2026-11-15
- Status: accepted (Pedro, 2026-11-15: "review the root .text-container, remove the padding, so it aligns with the width of the content nav-wrapper")
- Context: DR-0002 (edge-alignment T9) gave the root `.text-container` a 16px side padding (`_textelements.scss:468-471`) so body text sat on the nav's 16px page margin. Measured pre-change (evidence/t41-pre-change.json, probe t41-probe.py, build served at 1440/1024/916/768/600/390/320 on /workflow/, /styleguide/, /resume/): the `.text-container` border box already equals the nav `.content.nav-wrapper` box at every width (boxAlign YES everywhere), but its CONTENT box is inset 16px per side at every width (content 884 vs nav 916 at 1440; 358 vs 390 at 390). Pedro now wants the container to align with the nav-wrapper's WIDTH - content edge to edge with the nav box.
- Decision: the root `.text-container` carries no side padding at any width. Concretely, every rule that sets `.text-container` side padding is zeroed (side padding only - the vertical rhythm, 32px/128px top/bottom per band, is untouched):
  1. `_textelements.scss` root rule (all widths, 0,1,0, last in cascade over the per-band `padding: 32px` shorthands): `padding-left/right: 16px` → `0`. The rule must STAY as an explicit 0 - deleting it would let the per-band 32px sides back in.
  2. `tabs.scss` `[data-vb-panel='designsystem'] .text-container` (0,2,0, max-width 915px): sides 16 → 0. Without this, the design panel (and /styleguide/, which carries `data-vb-panel="designsystem"` since DR-0012/T40) keeps 16px below 916.
  3. `_resume.scss` `#resume_container .text-container` (1,1,0, all widths): sides 16 → 0. Without this, /resume/ keeps 16px at every width.
  4. `_grid.scss` `.section .text-container` in the 480-767px band (0,2,0): `padding: 128px 32px` → `128px 0`. Without this, the 32px sides resurface at 480-767 once rules 2-3 stop overriding. (The <=480 bands already carry `128px 0`.)
- Verified before changing anything: a headless-browser simulation injecting exactly these zeros (same specificity, no !important for the root-rule case; !important run for the end state) makes the `.text-container` content box equal the nav-wrapper box at every probed page/width (contentAlign YES 1440/768/390; full matrix in evidence/t41-verify.md).
- Rationale: the nav-wrapper `.content` (`_base.scss:101`) is `max-width: $content-width (916px); margin: auto` with NO padding - its box IS the page column. The text-container's box already matches it (width/max-width 916, margin auto, border-box); only the padding inset the content. Zeroing the sides makes content width == nav-wrapper width: 916 at >=916 viewport, full-bleed vw below.
- Consequences: supersedes the `.text-container` clause of edge-alignment DR-0002 (T9) - body text in root text-containers no longer sits on the nav's 16px text margin; it spans the nav BOX. Untouched, deliberately: the nav's own edge-text rule (`nav.scss` `ul a:last-child { padding-right: 16px }` - nav labels keep their margin inside the bar), `.hero .content` 16px (`hero.scss:18-20`), `#styleguide_container .case-study.document-text` 16px at <=915 (`_case-study.scss:1233`) - those pad other elements (hero text, the case-study text-box column), not the root `.text-container`. Text measure in root containers becomes 916 (was 884) at desktop, vw (was vw-32) below 916. The edge-alignment T10 probe contract (content at nav box ±16) will FAIL for `.text-container` by design - that probe belongs to the superseded DR-0002 contract; gallery cards, .text-box and the hero keep the 16px margin.
- Consequence fix (required by the change, measured): the case-study demo components inside the guide (.cs-metrics margin -16px, .cs-quotes/.cs-twocol margin -28px capped -8px <=915, .cs-timeline li -8px) sized their bleed for the container's old 16px gutter. With the gutter gone they spilled 16-28px of horizontal scroll on /styleguide/ and /workflow/'s design tab at <=972 (at 916 a 12px hole pre-existed). Fixed scoped to #styleguide_container at <=971px by shifting the bleed margins +16 (metrics 0, others 8px) - identical screen positions, no overflow; real case-study pages are untouched (their .text-box keeps the gutter and the global <=915 cap).
- Non-goals: no change to vertical padding/rhythm, no width/max-width changes, no markup changes, no changes to nav, hero, case-study text-box, gallery cards, or image bleeds.
