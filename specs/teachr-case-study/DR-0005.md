# DR-0005: move the app callout to the designs jump-in, training deep link, design-system link hover, stacked avatar-menu shots

- Date: 2026-11-20
- Status: accepted
- Context: follow-up pass on `/selected-works/teachr/` after DR-0004. Four requests: (a) the `try-app` callout sits at the very bottom (after ai-workflow) where nobody reaches it — it belongs where the page jumps into the designs; (b) the callout links the app's dashboard landing, but the case study is about the training flow; (c) on the teal page, links hover to red text on a red plate (measured: `.cs-related a` hover = color #cd3231 on background #d73735) because the theme's base `a` color out-specifies the global `a:hover` — the exact failure mode the home/about/styleguide/resume recipes already guard against by repeating the states at theme specificity; (d) the avatar-menu pop-out + settings pair should stack vertically, not sit side by side.
- Decisions:
  1. **Callout moves up**: the `## Try the mock app | Live demo | try-app` section moves from after `ai-workflow` to right before `## Redesigning participant registration | Detail | registration` — the first Detail deep-dive, i.e. where the page jumps into the designs. Copy unchanged.
  2. **Training deep link**: the callout href becomes `../teachr-app/?view=library`. In `src/teachr-app/wizard.js` the boot reads `?view=library` as the library tab ("opened by Start training"), booting into the registration gate on first entry and the training list afterwards — the training experience, not the dashboard (plain `../teachr-app/` lands on the dashboard).
  3. **Link hover uses the design system**: the global recipe in `_typography.scss` (base `$vb-primary` + underline; hover/focus light text on `$vb-primary` plate, no underline; active `$vb-secondary` plate) is repeated at theme specificity in `.case-study.cs-teal a` and at `.case-study .cs-related a:hover/focus/active`, matching the established pattern in `_pages.scss` (home/about/styleguide) and the dark workflow block. No new link style invented.
  4. **Avatar-menu stacks**: the two image lines in the `avatar-menu` draft split into solo images, each with its own `Caption:` line, so the converter emits two showcases instead of one `::: wide` run. Tiers come from `showcaseTier` for free: the pop-out (626x316, ratio 1.98, w<1800) renders on the default tier; the settings phone capture (660x1392, ratio 0.474) renders on the `cs-showcase--tall` tier (max-width 480, centered). Stacked, centered, no CSS hacks — the DR-0004 `#avatar-menu .cs-shots` override is removed (the run no longer exists).
- Consequences: the `::: wide` image-run rule is untouched (other sections keep their runs); `#avatar-menu` CSS from DR-0004.5 is deleted; link hover on the teal page now matches every other light page (red plate, light text) instead of red-on-red.
- Evidence: Playwright hover probe before fix (related link: `color rgb(205,50,49)` on `bg rgb(215,55,53)`); after fix in `evidence/polish2-verify.md` + captures.
