# DR-0002: Group related screenshots into side-by-side `::: shots` runs (desktop next to mobile)

- Date: 2026-11-18
- Status: accepted
- Context: after the PDF fold, related captures sat as separate stacked showcases (library desktop/mobile, avatar pop-out/settings) or as stacked inline images inside compare panels (lessons questions, completion). The PDF presents them side by side; stacked, they read as a long scroll of near-identical screens.
- Decision: pair related shots as image runs that render in one full-bleed `::: shots` band (`.cs-shots`, flex, each shot's alt text as its caption, wrapping to a stack under ~240px per shot on phones):
  - library: desktop + mobile course library
  - avatar-menu: avatar pop-out + settings
  - lessons: question desktop + question mobile + scroll-to-next button (moved out of the compare panel to the top of the section, after the frame-184 showcase)
  - completion: lesson-complete desktop + mobile (moved before the compare panels)
  - registration frame-181, lessons frame-184, assistant chat, feedback emphasis and frame-187 stay solo showcases (single wide/tall assets, tier per DR-0004 showcase rules)
- Mechanism: `specs/text-to-md/tools/draft-to-md.js` now implements rule 6b exactly as documented in `specs/text-to-md/DR-0004.md` and the visuai-text-to-md skill — 2+ consecutive `![alt](src)` lines with no blank line or `[caption:]` between them emit one `::: shots` fence; a solo image keeps the showcase-with-caption behaviour. The rule previously existed only in the DR/skill text, not in the reference implementation; the code now matches the documented contract. No other page md changes (no other draft has consecutive image lines outside groups).
- Consequences: captions on grouped shots live in the alt text (rendered as figcaption in the band); removing a shot from a run = deleting its line. Deep-dive section ids unchanged (the completion heading was normalised back to the 3-part form `## Completion | Detail: Completion | completion` so the id stays `completion`).
- Evidence: `specs/teachr-case-study/evidence/teachr-{1440,390}-band-*.png`, `teachr-1440-full-final.png`.
- Refinement (same day): shots in a band now share one height - `renderShots` sets each figure's `flex-grow` to the image's own aspect ratio (dims read at render time like the showcase tiers), so a mobile capture renders at the desktop capture's height next to it, just narrower. `markdown-render.js` + `.cs-shots` comment + AUTHORING.md/styleguide blurbs updated. Along the way the showcase-rewrap pass in `applyAiMarkers` was taught to skip images inside an unclosed `cs-shot` figure (the wider inline style had pushed the old 30-char lookback past the class name, so wide shots were being double-wrapped in a full-bleed showcase and overflowing their shot). Verified at 1440: every band's image heights are equal (749/749, 580/580, 839/839/838, 684/684); at 390 the shots wrap and stack full-width as before. Evidence: `teachr-{1440,390}-band-*-v6.png`.
