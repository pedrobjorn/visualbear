# DR-0001: The markdown conventions are the authoring contract

- Date: 2026-10-29
- Status: accepted
- Context: Case-study content is transformed by regex post-processing on marked output (`gulp/markdown-render.js`). The mapping (h1→hero, first para→summary, tables→cards, etc.) lives only in code comments, so authors must read build code to write content. Alternatives considered: structured frontmatter + templates (more machinery, breaks the "just write markdown" goal); a rich-text editor (rejected, see plan non-goals).
- Decision: The plain-markdown conventions documented in `markdown-render.js` are the contract. They get promoted to an author-facing guide (Ticket 1); the guide and the code comments must stay in sync, guide wins on conflict.
- Consequences: New md features (e.g. a new block type) require updating both the renderer and the guide in the same change. Convention-driven derivation (no frontmatter) remains the default until DR from Ticket 2 says otherwise.
