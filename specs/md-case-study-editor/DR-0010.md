# DR-0010 — List context decides the component: chips at section level, plain bullets inside boxes

- Date: 2026-10-31
- Status: PROPOSED — pending Pedro's confirmation (reference-set call)
- Extends: DR-0009 (one text edge; bullets may take the +8px indent)
- Context: ticket 22 deferred chip-vs-bullet to Pedro's content call.
  This record settles it structurally, using the three reference pages
  (sports-ecommerce-redesign, teachr, digital-closet) as the standard.

## Decision

The same markdown list (`- item`) renders as different components by
context, and that split is now the rule, not a renderer accident:

1. **Section level** — `- item` → `ul.cs-facts` fact chip (bleeding
   plate, dot 8px before the text).
2. **Inside a box** (`::: cards`, `::: columns`, `::: compare` panels) —
   `- item` → plain bullet: dot on the text edge, text +8px, no plate.
   A plate inside a plate doubles the visual noise; no reference page
   nests chips in cards.
3. **Explicit opt-out** — `* item` renders a plain bullet list at
   section level, for short enumerations that should not carry the chip
   weight (e.g. ecommerce's three KPI lines, if Pedro demotes them).
4. **Numbered lists** (`1. step`) → timeline in both contexts, unchanged.

## Why

- The reference set already behaves this way (audit 2026-10-31:
  ecommerce 8 chip lists at section level, plain lists in all 3 research
  cards; closet chips for Ideation, plain lists in the Win/Hard-truth
  columns; teachr chips for Research findings). The rule documents what
  the pages Pedro approved actually do.
- The current split exists only because `renderFlow` (container bodies)
  and `mdPage` (section bodies) use different marked renderers. If it
  stays implicit, the next container type silently changes bullet
  appearance — exactly the class of accident tickets 18–23 spent a day
  eliminating.

## Consequences

- `markdown-render.js` must be able to distinguish `-` and `*` lists
  (marked's list renderer does not see the marker character — the
  renderer tags list runs by their source marker, see Ticket 24).
- AUTHORING.md's convention table changes from "`- item` → Fact chips"
  to the context rule + the `*` escape hatch.
- The edge-audit tolerance stays: list text at edge +8px ±2, everything
  else on the edge (DR-0009 amendment, ticket 19).
