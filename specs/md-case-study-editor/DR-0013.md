# DR-0013 — One content width everywhere: the resume's 900/836

- Date: 2026-10-31
- Status: ACCEPTED (Pedro, 2026-10-31: "unify all pages with the same
  content width matching the resume content width")
- Context: measured width matrix, 2026-10-31 — the resume's content
  container is 900px (text extent 836 after its 32px padding) while
  EVERY other page (case studies, workflow, home, about, visualbear,
  all gallery pages) runs the shared `.text-box` at 768px (content
  736). Two content widths site-wide, 64px apart.

## Decision

1. **One content width**: `.text-box` matches the resume's
   `.text-container` — `width: 900px` (with `max-width: 100%` below
   992px), `padding: 0 32px` — content extent 836px, the resume's.
   Applies to every page using the shared container (all of them).
2. The four wide `.text-box` variants in `_gallery.scss` (≥2400,
   1280–2399, 992–1279, 768–991) all move to the same values; the
   ≤767 variants (100% / 32px) are unchanged.
3. The bleed invariant bump (ticket 31) widens from ≤839 to ≤907:
   with the 900px container, text edge = (vw−900)/2 + 32; it stays
   ≥ 36px (28px bleed + 8px viewport margin) only down to vw = 908 —
   the bump carries the band below that.
4. Resulting geometry at 1440 (was → now): text edge 352 → **302**
   (= the resume's measured 302), bleed edge 324 → **274**. The
   full-bleed tier (cs-wide, 100vw + left:50%/−50vw) is parent-width-
   agnostic — unchanged.

## Tradeoff (recorded)

836px at the 18.432px body size ≈ 87 characters per line — above the
~80-char comfort guidance for sans-serif. Accepted: the resume has run
this width since its migration and Pedro chose it as the standard.
If it reads long in practice, the fallback is a `max-width: 800px`
cap on body paragraphs only — NOT built (spec'd here as the veto path).

## Consequences

- Every page's content column widens 64px at ≥992 viewports; the
  non-migrated gallery pages inherit the same width automatically
  (they share `.text-box`) — unification is site-wide by construction.
- All case-study edge numbers in older tickets/DRs (352/324 at 1440)
  shift to 302/274; the audits derive edges dynamically and are the
  source of truth, not the historical numbers.
