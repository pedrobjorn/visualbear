# DR-0006: AI-attribution marker for AI-written content

- Date: 2026-10-29
- Status: superseded by DR-0007 (was aimed at the wrong page; visualbear changes reverted)
- Context: The visuai page's hero, quotes demo, and first section were AI-drafted. Pedro wants AI-written content marked subtly on the page and the marking recorded in the md source, so authorship stays legible and AI copy never ships unnoticed.
- Decision: A block-level `[ai]` marker in the markdown source. The renderer attaches `data-ai="true"` to the marked block; CSS renders a subtle sparkle chip ("✦ AI", low-contrast, decorative) on the dev server only. Production builds strip the attribute — so the chip can never ship — and print a loud per-page warning listing the AI-attributed block count. Blocks opt in; the marker never renders as body text. One-off graphics that can't be markdown (the venn) live as named partials in `src/_data/patterns/`, referenced with `[figure: name]`.
- Consequences: New visual components require extending the renderer and `AUTHORING.md` together. The deep rule lives in the skills: `visuaibear-review` Gate 7 blocks any review finding AI-attributed content in a shipped build; `visuaibear-core` non-negotiable #7; `visuaibear-spec` templates note the convention. Pedro rewrites in his own voice, then removes the marker — never removed on his behalf.
