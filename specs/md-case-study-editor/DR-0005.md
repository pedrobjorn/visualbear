# DR-0005: Pure-markdown content files — visual components expressed as syntax

- Date: 2026-10-29
- Status: accepted
- Context: The user's direction — "these should only be markdown" — superseded the earlier approach of keeping bespoke layout HTML inside the content files. The renderer gained a container/directive vocabulary so content files contain only markdown and bracket directives, while the page shell keeps the hero and chrome.
- Decision: Visual components that markdown couldn't express get first-class syntax in the `mdpage`/`mdresume` pipeline: `::: metrics`, `::: compare`, `::: showcase`, `::: cards`, `::: columns` containers plus single-line directives `[intro:]`, `[note:]`, `[point:]`, `[figure:]`, `[h2:]`, `[h3:]`, `[divider:]`. One-off graphics live as named partials in `src/_data/patterns/*.html`, referenced with `[figure: name]`. The mdResume parser handles nested lists (skills tree) and quiet sections (`## Title |` → `div.sub-title` instead of `h3`).
- Consequences: Content files are pure markdown + directives, editable without touching templates. New visual components require extending the renderer and this guide together. The legacy double-row wrapper in the resume skills section is intentionally not reproduced.
