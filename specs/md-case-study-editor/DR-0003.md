# DR-0003: Section overrides + renderer-scoped list classes (learned from Ticket 3)

- Date: 2026-10-29
- Status: accepted
- Context: The existing case-study pages use eyebrow labels that differ from their h2 headings and hand-chosen section ids (e.g. eyebrow "Exploration", h2 "Research", id "research"). They also embed bespoke raw HTML (venn figure, comparison panels, two-column lists). Pixel-identical migration broke three ways: (1) `##` sections couldn't set a different eyebrow/id; (2) the renderer's global `<ul>`→`cs-facts` regex rewrote raw-HTML lists, applying chip styling to plain lists (visually different — `.cs-facts li` gets card backgrounds); (3) marked 0.3.19 entity-escapes text inside raw HTML blocks (`&quot;`, `&#39;` — visually identical, accepted).
- Decision: (1) `## H2 | Eyebrow | id` — both overrides optional, id defaults to slug(eyebrow). (2) List classes are applied in marked's list renderer (markdown-generated lists only); raw-HTML lists pass through untouched — the global regex rewrites are gone. (3) Bespoke blocks that the conventions can't express stay as raw HTML inside the md file (documented passthrough); the hero and hero-meta sections stay in the page shell when they carry bespoke layout (e.g. `cs-hero--red`, metrics), because mdPage's hero derivation would mangle raw heroes.
- Consequences: Authors override eyebrow/id with the pipe syntax when the design needs it. Raw HTML in md must not rely on the renderer adding classes. Future heroes that only need title/summary/details use the md conventions; custom hero variants stay in the shell.
