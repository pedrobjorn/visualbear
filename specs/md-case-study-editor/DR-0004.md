# DR-0004: Raw HTML is extracted before marked and spliced back via placeholders

- Date: 2026-10-29
- Status: accepted
- Context: While migrating fashion-rebrand (Ticket 4), marked 0.3.19's html-block state machine intermittently swallowed headings that followed large raw-HTML blocks, emitting them as literal text. Debugging showed the failure was content-dependent (the same heading parsed in isolation). Fighting a 2015 parser's internals block by block is not maintainable.
- Decision: `renderMarkdown` now extracts block-level raw HTML (tag-balance scan, line-based, HTML comments included) from the source before marked runs, replaces each block with a `@@RAWn@@` placeholder padded with blank lines, runs marked on clean markdown, and splices the raw blocks back (unwrapping the `<p>` the placeholder gets wrapped in). Raw HTML therefore passes through byte-for-byte by construction, and headings always lex in clean markdown context.
- Consequences: Raw HTML blocks must be balanced tag-wise for the scanner (unclosed tags trap following content — same as markdown semantics). Inline HTML inside markdown paragraphs still goes through marked. The authoring guide's "raw HTML passes through" is now guaranteed structurally, not by marked's mercy.
