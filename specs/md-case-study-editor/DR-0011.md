# DR-0011 — `[point:]` under an image is a caption: dotless, italic

- Date: 2026-10-31
- Status: PROPOSED — pending Pedro's confirmation (recommended: full
  figcaption treatment; vetoable to left-aligned italic)
- Context: Pedro, 2026-10-31 — "Remove the dots from the text below
  images? If these are text caption text style it accordingly as
  italic."
- Supersedes: the annotation-dot treatment for `[point:]` lines that
  follow an image/frame (ticket 33's in-box containment, and the
  DR-0009 gutter-hang exception for annotation points)

## Decision

A `[point: text]` directive that follows an image/frames line (a
`[frame:]` / `[image:]` / `![alt](src)` / `[figure:]` line) in the same
container is a **caption**, not an annotated point:

1. **No dot.** The `.cs-annotation-dot` is not rendered for
   image-following points.
2. **Caption styling**: italic, label tier (15.36px), quiet ink
   (#5f6264 — the axe-verified caption color), centered under the
   image, matching the existing `.cs-showcase figcaption` treatment.
3. **Semantics**: render as part of the image's figure (a figcaption)
   where the markup allows, so image + caption stay one accessible unit.
4. `[point:]` lines NOT following an image keep the annotation-dot
   treatment (ticket 33 rules: gutter hang at section level, contained
   in-box) — none exist in the content today; the rule is for future pages.

## Why

- All 8 current `[point:]` usages (fashion 3, ecommerce 5) sit directly
  below `[frame:]` placeholders inside `::: compare` panels — they are
  captions in content, dots in styling. The dot reads as a stray bullet
  on caption text (the same class of confusion as ticket 19's "I didn't
  say remove bulletpoints" — visual role must match content role).
- The caption tier already exists (figcaption: centered, label size,
  #5f6264, axe-verified 5.4:1); reusing it adds no tokens and keeps
  image annotations visually distinct from body bullets — which the
  bullet rule (dots, DR-0009 amendments) now defines precisely.

## Consequences

- `.cs-annotation` keeps its dot for non-image contexts; the
  image-following variant needs renderer support to distinguish context
  (it already parses panel bodies line-by-line in `renderFlow` — the
  preceding line's directive type is known at render time).
- edge-audit already exempts annotation context from the text-edge
  check (`isAnnotation`); centered caption text stays exempt as a
  display element.
- AUTHORING.md: `[point:]` documented as "image callout / caption when
  it follows an image; annotation dot otherwise" (ticket 29 sync).
