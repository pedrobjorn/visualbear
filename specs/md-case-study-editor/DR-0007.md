# DR-0007: AI-attribution applies to the visuAI page only; clearer placement

- Date: 2026-10-29
- Status: accepted
- Supersedes: DR-0006 (partially — the mechanism stays, scope and styling change)
- Context: DR-0006 was implemented against the wrong target — the visualbear (brand identity) page — based on a misreading of "visuai page". The visuAI page is `/workflow/` ("My Agentic Design Workflow", the page with the visu AI wordmark). The visualbear page changes were reverted in full (shell restored via git, `visualbear.md` deleted). The corner chip was also too subtle to notice.
- Decision: The AI-attribution marker applies ONLY to the visuAI page (`/workflow/`). The marker becomes more prominent: rendered **inline with the content or above the container** (e.g. an "AI-drafted" label/chip line above the marked block), not a corner badge. The mechanism stays: `[ai]` in the md source → marker in the rendered page on localhost only; production strips it and warns (the deep rule stands: `visuaibear-review` Gate 7, `visuaibear-core` #7).
- Consequences: `/workflow/` content moves fully into the md pipeline (its `workflow.md` exists but the shell is not wired — that becomes the migration ticket). The visualbear page stays untouched. The CSS chip style is replaced by the inline/above-container label on the workflow page only.
