# DR-0017 — link-state specificity rule: theme/base link colors must repeat the global link states

- Date: 2026-11-20
- Status: accepted (shipped in the teachr-case-study pass 2, specs/teachr-case-study/DR-0005 ticket 21)
- Context: the design-system link recipe lives in `_typography.scss`: base `a { color: $vb-primary; underline; font-weight 600 }`, hover/focus = light text on a `$vb-primary` plate with no underline, active = `$vb-secondary` plate. Several pages already guard it by repeating the states at the same specificity as their base color (home/about/styleguide/resume in `_pages.scss` / `_resume.scss` — the comments there name the failure: "an id-level base color would otherwise beat the global a:hover rule and leave dark red text on the red hover plate").
- Bug found on the teal case-study page: `.case-study.cs-teal a { color: #cd3231 }` (0,2,1) out-specified the global `a:hover` (0,1,1), so hovered links kept dark-red text while gaining the red plate — measured rgb(205,50,49) text on rgb(215,55,53) plate.
- Decision (standing rule): **any case-study theme or component that overrides a link's base color must repeat hover/focus/active at equal or higher specificity, using the global recipe verbatim.** Applied: `.case-study.cs-teal a` and `.case-study .cs-related a` now carry the states; `.cs-callout .cs-callout-link` pins its own pill states (white on `--cs-accent-deep`) so theme link rules never recolor it.
- Consequences: pink/black/default themes were checked — they do not override `a` base color, so they are unaffected. Future theme link overrides must follow this DR (review gate: hover computed color must be `$vb-light`, not the base ink).
- Evidence: hover computed styles before/after in `specs/teachr-case-study/evidence/polish2-verify.md` (T21 row).
