# DR-0009 — Case-study layout: one text edge, bleeding boxes, full-bleed tier

- Date: 2026-10-29
- Status: ACCEPTED (Pedro approved the bleeding-boxes look: "the boxes can
  live within the bleed"; full-bleed tier requested same day)
- Supersedes: the ticket-18 "tier system" (multiple indent tiers)

## Decision

The case-study layout has exactly **two horizontal containers** and one
optional extension:

1. **The text edge** — every body-level element (paragraphs, list text,
   boxed content, timeline step text) aligns here. One edge, ±2px.
2. **The bleed** — boxes (cards, fact chips, summary, quote-group cards)
   extend one `$cs-indent` (28px) step into each gutter past the text
   edge; their text stays on the text edge. Below `$break-small` the
   bleed and padding shrink to 16px.
3. **The full-bleed tier** (opt-in and default for media) — images
   (showcases), tables and background-flagged containers span the full
   viewport width (`100vw` technique, padding 0), edge to edge.

Markers (list dots, annotation dots, timeline numbers) hang in the
gutter, outside the text edge. Quotes are display elements everywhere
(centered, italic, h2-size) — never plain paragraphs. The hero summary
box is a display element (centered text in the centered hero).

## Why

Five measured left edges for body-level content (345/361/373/381/389)
made the pages unscannable; body copy scattered across sizes. One edge
plus bleeding boxes keeps the calm editorial rhythm while letting
components keep their containers. Full-bleed exists because media and
tables were "wider but not wide" (the cs-wide wrapper's 48px inset) — a
half-measure that read as a bug.

## Consequences

- `$cs-indent` is the single spacing token for the indent system.
- The bare `nav` element styles had to be scoped (`nav.site-nav`) — any
  future `<nav>` must not inherit the fixed site-header styles.
- Full-bleed images upscale small sources; authors should use
  reasonably large images (noted in AUTHORING.md).
