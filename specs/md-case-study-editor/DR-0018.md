# DR-0018 — metrics row fits 4-across at ≥768px; shots-row min-width clamp only below 768px

- Date: 2026-11-20
- Status: accepted (shipped in the teachr-case-study polish pass, specs/teachr-case-study/DR-0004 tickets 15-16)
- Context: two shared-component layout bugs found by measurement on `/selected-works/teachr/` at 1440/1280:
  1. `.cs-metric { flex: 1 1 200px; margin: 16px }` — 4 × (200+32) = 928px > the 916px meta measure, so 4 KPI cards wrapped 3+1 (measured: three 273px cards at y796 + one 884px card at y978).
  2. `.cs-shots .cs-shot { min-width: 240px }` clamped the renderer's aspect-ratio-proportional `flex-grow` whenever a phone shot's proportional width < 240px, so its image rendered taller than its desktop sibling in the same row (measured at 1280: completion mobile 506px vs desktop 438px; at 1440 pre-fix: avatar-menu settings 506 vs pop-out 416).
- Decision:
  - At `min-width: $break-medium` (768px): `.cs-metric { flex: 1 1 0; min-width: 0; margin: 16px 8px; padding: 24px 12px }` → all KPI cards share one row (measured 4×213px at one y at 1440 and 1280). Below 768px the wrap stays (2x2, then 1-per-line on phones).
  - At `min-width: $break-medium`: `.cs-shots .cs-shot { min-width: 0 }` → widths stay proportional to aspect ratio, so every shot in a row shares one height at every desktop width (verified within 2px at 1440 and 1280). Below 768px the 240px floor stays, so phones still stack.
- Consequences: shared rules — every case-study page's metrics row and shots rows behave the same (intended; the shots comment already documented "all shots in a row share one height"). The `#avatar-menu` per-page override from DR-0004 was removed in DR-0005 (the pair became solo showcases); no per-page shots hacks remain.
- Evidence: measurements in `specs/teachr-case-study/evidence/polish-verify.md` (T15/T16 rows) and captures there.
