# DR-R4-0002: The air-locked path supersedes the teachr password gate (A2)

- Date: 2026-11-02
- Status: accepted (supersedes the A2 decision in
  `../md-case-study-editor/plan-teachr-password.md`; DR-0015 there was
  never written)
- Context: `plan-teachr-password.md` specced a PHP session gate for
  `/teachr/` (custom HTML gate page, bcrypt hash above the web root,
  guard script - TP-3a built and tested). Pedro's release 4.0 brief
  moves the bar: "It'll be a good enough solution instead of a password.
  Essentially, information will be the password."
- Decision: Drop the gate. teachr, teachr-agent, and workflow leave the
  public build entirely (404 at their old URLs) and exist only under the
  air-locked mirror path. The built-but-never-gated artifacts
  (`src/teachr/index.php`, `scripts/teachr-guard.sh`,
  `scripts/build-protected.sh`) are retired in R4-6; the guard discipline
  (fail loudly before publish) carries into the new release guard (R4-4).
- Rationale: Moving the pages is strictly stronger than gating them at
  the same host: there is no gate to bypass, no bypass file to guard, no
  hash to manage, no PHP in scope. The threat model is unchanged (keep
  pages away from clients, recruiters, and crawl - not from a determined
  attacker), and a URL nobody can know meets that bar. The mirrored
  copies are outside any public reference surface (no sitemap, no
  robots.txt entry - robots DISALLOW would advertise the path - no
  nofollow'd link), so crawlers have no discovery vector either.
- Consequences: Anyone previously sent `/teachr/` links loses access;
  they need the new mirror URL from Pedro. The `secure`-cookie and
  session work in TP-3a is abandoned. Hash generation steps
  (`password_verify`, `.phash`) never happen.
