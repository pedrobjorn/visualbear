# DR-R4-0003: Air-locked zone = full-site mirror under the secret path

- Date: 2026-11-02
- Status: accepted
- Context: Pedro asked for "a sub-path duplicate of the web page" and,
  when asked to choose scope, leaned toward "a url containing a PDF
  portfolio that links to the main site - is cleaner", but had already
  decided that teachr/teachr-agent/workflow must be REMOVED from the
  public build and live "only under the secret path". A PDF-only page
  cannot host those pages, so the two answers pin the choice.
- Decision: The mirror is a full copy of `build/` one directory deeper,
  produced by a post-build script. Pros that settled it:
  - Mechanical, near-zero design work: relative URLs (`../images/...`,
    `../teachr/`) keep resolving because the structure is reproduced;
    the handful of root-absolute URLs (`/`, `/styles/main.css`,
    `/scripts/main.js`) hit the live public site - the mirror links back
    to visualbear.com, which Pedro explicitly wanted.
  - The public-vs-private rule is a pure file move (3 directories),
    no template branching, no path-rewrite logic.
  - Recruiters get one URL containing the complete portfolio including
    the three unlisted md case studies.
    Alternative rejected: the one-page/PDF drop-in - cleaner and smaller,
    but it strands the teachr pages somewhere publicly reachable anyway,
    contradicting the "move to secret path" decision. Revisit if the
    doubled FTP upload (~42 MB -> ~84 MB) hurts: a later optimization can
    exclude `/images` from the mirror and load shared assets from the site
    root (documented in the plan's open questions).
- Consequences: Every publish uploads both zones; the release guard must
  verify the prune step ran (public `<slug>` dirs absent, mirror copies
  present) or the "moved" guarantee silently degrades.
