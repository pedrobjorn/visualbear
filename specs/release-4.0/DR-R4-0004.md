# DR-R4-0004: Slug = innocuous word + random suffix; path hygiene rules

- Date: 2026-11-02
- Status: accepted; value scheme = short random tail (invisible-char
  variant considered and rejected 2026-11-02, see Context)
- Context: The air-lock's entire security is "information is the
  password". Pedro's constraint: "not easily guessable but also not
  suspicious for recruiters - make it seem harmless" (e.g.
  `selected-works`, not "secrets-to-hide-from-employer"). An
  invisible-character path (zero-width codepoints at a hidden position)
  was proposed and evaluated 2026-11-02: it FAILS this use case -
  browsers percent-encode zero-width chars, so the address bar shows a
  corrupted-looking `selected-works%E2%80%8B`; mail clients and link
  sanitizers strip zero-width chars (anti-watermarking hygiene), so the
  invitation link can silently 404 in transit; entropy is only
  position x few codepoints (hundreds) - WEAKER than random; and an
  invisible char in a directory name poisons FTP/grep/backups.
- Decision:
  - Shape: `<harmless-phrase>-<6 lowercase alphanumerics>`, generated
    with a CSPRNG (`crypto.getRandomValues`; 36^6 ~ 2e9). The suffix
    does the unguessing; the phrase does the fronting. Phrase chosen
    with Pedro 2026-11-02: `selected-works`.
  - Hygiene (the actual lock):
    1. The real value lives in `src/_data/private-path.json`,
       gitignored; only a `.example` placeholder commits.
    2. Never in `sitemap.xml` (nothing), never in `robots.txt`
       (a DISALLOW line advertises the path to anyone reading it),
       never in any public-page HTML, nav, or footer.
    3. Every mirrored page carries `noindex` so IF a crawler somehow
       learns a URL it still stays out of indexes.
    4. The release guard greps repo and build for leaks outside the
       mirror before any publish.
  - Not required: changing the value on rotation - regenerating the
    config file and rebuilding re-seats the lock; old URLs simply 404.
- Rationale: 6 lowercase alphanumerics = 36^6 ~ 2.2e9 combinations; no
  dictionary or path-scanning attack finds it, and nothing points at it.
  An innocuous front matters because the URL appears in plain email
  threads and calendars.
- Consequences: The URL is shared in the clear (email) and appears in
  application tracking systems - accepted at the stated bar; rotate the
  value if a leak is ever suspected.
